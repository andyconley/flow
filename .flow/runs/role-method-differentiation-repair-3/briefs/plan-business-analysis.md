# Planning brief: acceptance traceability

## Role

Act as Flow's business-analyst. Turn the approved requirements into an
implementation-ready workflow and acceptance map.

## Inputs

- `requirements.md`
- `acceptance-criteria.md`
- `evidence/start-receipt.json`
- `evidence/preservation-inventory.json`
- `evidence/release-evidence-map.json`

## Questions to answer

1. Which exact active surfaces must change for the six-role final state?
2. Which states and transitions must the implementer record from working tree
   through review, merge, release, install refresh, and two live clients?
3. How should each acceptance criterion map to an observable artifact or check?
4. Which wording or scope ambiguity could let an incorrect result pass?

Write the result to `research/plan-business-analysis.md`. Do not edit production
files or protected evidence.

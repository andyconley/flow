# Supervised MAF runtime implementation

`cli.maf_supervisor.run_maf(envelope, on_propose, *, timeout_s=120, python_path=None)` is the parent-side boundary. It selects `python_path`, `FLOW_MAF_PYTHON`, then the current interpreter, launches `python -m runtime.maf_runner` without a shell, and supplies a minimal child environment containing only `PYTHONPATH`.

The protocol uses bounded JSON lines (`protocol_version: 1`). The parent sends exactly one `start` record. The child emits one `propose_action` record containing the stable attempt/action identity, route and digest fields; Flow recomputes action identity and validates all proposal fields against the immutable envelope before it invokes `on_propose`, then replies with one normalized `action_result`. The child returns `workflow_finished` with its attempt ID, nullable checkpoint ID and summary. The parent reads stdout with a bounded `os.read`/`select` buffer rather than `readline`, so a partial child line cannot bypass the monotonic deadline. It also requires exit code zero before accepting `workflow_finished`. Invalid JSON, missing fields, unsupported versions/types, EOF, an extra proposal, timeout, changed identity, nonzero post-terminal exit, or child error raises a parent-side failure and kills the child. Flow retains any already-recorded parent-side provider outcome for its gateway to mark as failed or unknown.

MAF imports are confined to `runtime/maf_runner/__main__.py`. The child builds a real `MagenticBuilder` with a deterministic one-call `MagenticManagerBase` and a custom `GuardedSpecialist`. The specialist has no raw agent input, client, provider invocation, ledger access, or provider credentials. It only emits a proposed action and sends Flow's normalized result back into the MAF workflow. The child accepts only `test-engineer` with `ollama` or explicitly labeled `local-stub` routes. When Flow supplies an absolute checkpoint directory, it uses `FileCheckpointStorage` and returns the newest checkpoint ID where the installed MAF version provides one. The opt-in dependencies are pinned in `runtime/maf_runner/requirements.txt`; no Ollama or other provider package is part of the child.

Tests should exercise this boundary with the MAF virtual environment through `python_path`: successful one-proposal round trip, callback denial, malformed child output, a child that emits a partial unterminated line and stalls, child EOF/error, nonzero exit after a terminal record, timeout, no-MAF interpreter diagnostics, and confirmation that the ordinary CLI imports `cli.maf_supervisor` without importing `agent_framework`. The failure tests also assert child pipe handles are closed after reaping, so a local CLI run does not leave descriptors for the garbage collector. The gateway owns tests that prove an adapter is never invoked before Flow grants it.

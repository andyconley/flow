# First MAF adoption slice: integration plan

## Scope and architecture boundary

Andy selected a **foundation/contract slice** whose first runnable milestone is one guarded local worker launched through the Flow CLI. Codex, Claude, MCP ingress, multi-worker scheduling, delegated Shaper approvals, and automatic recovery are later slices. This is an implementation plan, not a claim that the current CLI already executes MAF. The accepted [adoption design](../../../../docs/maf-adoption-design.md) and [ADR 0011](../../../../docs/adr/0011-supervise-maf-behind-flow-gateway.md) fix the packaging choice: an optional supervised MAF child process behind a Flow-owned gateway.

Flow's present `cli/runstate.py` owns phase transitions through `run.json` and `events.jsonl`; `cli/orchestration.py` checks the declared manifest, not effective runtime grants. Preserve both contracts. Create execution attempts and the policy ledger beneath the existing `.flow/runs/<work_id>/` directory. Neither MAF nor the local worker may write `run.json`, `events.jsonl`, the execution ledger, or the receipt. The CLI invokes the gateway against an existing `implementing` run with a valid `orchestration.json`; the gateway, not the MAF child, decides whether a proposed action can reach a worker. A completed worker attempt produces evidence but does **not** automatically mark the run `handback_ready` or accept review.

The single local worker should use the effective `test-engineer` specialist definition resolved by Flow's existing framework/user-overlay merge (`cli/sync.py`), including a user override if one exists. Snapshot its rendered bytes and SHA-256 in the attempt before launch. Reject absent, ambiguous, or changed definitions; do not silently fall back to a stale generated Codex/Claude agent file. Its assignment and artifact contract must be explicit in the run manifest and launch request. The first implementation may call a local Ollama server, with a deterministic fake adapter for tests; it must label the two distinctly in results and receipts.

| 3. | 4. Supervised runner | New optional `runtime/maf_runner/` package and `cli/maf_supervisor.py` | Child process owns MAF workflow and checkpoints. | 6. CLI/docs/tests | Modify `cli/flow.py`, add focused `tests/test_execution_*.py`, update README/CLI help and operator notes | Add a `flow run execute-local <work_id>` command (exact flag spelling can follow existing CLI conventions) that requires an approved assignment and explicit task input. Display attempt ID, status, receipt path, and reconciliation need. No new lifecycle transition is required in this slice. |

The files above are proposed module seams, not a mandate to split trivial helpers into separate modules. They keep domain contracts, persistence, integration, and transport separate. `cli/runstate.py` should need at most a read-only status call; changing its transition table for worker status would conflate lifecycle with execution. `cli/orchestration.py` should remain the structural validator; the gateway adds semantic runtime authorization on top. Existing specialist definitions and generated adapters should remain unchanged.

## Minimal Flow-owned contracts

All records have `schema_version`, UTC timestamp where applicable, `work_id`, and `attempt_id`; unknown major versions fail closed. Canonical JSON (sorted keys, UTF-8, no NaN) supplies digests. The initial charter can be a **snapshot of the approved run requirements and execution envelope**, identified by digest, because no production Shaper charter schema yet exists. Do not describe it as a fully adopted Shaper charter. Later migrations can add a formal charter record without changing the gateway's stable references.

| Record | Required first-slice fields | Authority |
| --- | --- | --- |
| `ExecutionEnvelope` | `work_id`, `attempt_id`, charter source/digest/revision, orchestration manifest digest, assignment/artifact-contract digest, `test-engineer` definition digest, provider=`local`, allowed specialist instance, max delegations=6, max concurrent=3, max replans=2, paid budget=0, local timeout/output limits | Created and sealed by Flow before child start; child treats it as immutable. |
| `ActionRequest` | Stable `action_id`, `attempt_id`, `kind=delegate`, specialist role and instance, provider/model, task digest, parent action ID if any, proposed concurrency slot, sequence, envelope digest | Proposed by MAF guarded participant; no authority by itself. Derive ID from Flow attempt, charter digest, definition digest, instance, kind, and durable sequence. |
| `PolicyDecision` / `DispatchGrant` | Decision ID, action ID, allow/deny and reason, exact role/provider/model/task digest, envelope digest, one-use grant ID, expiry, reserved slot; no grant for denial | Committed by Flow. The supervisor consumes a grant atomically before invoking the local adapter; a repeated grant cannot dispatch again. |
| `ObservedResult` | Action/grant IDs, status (`completed`, `failed`, `unknown`), physical dispatch observation, provider/model/session reference, usage if supplied, output digest and bounded output reference, error category, start/end times | Recorded by Flow from the adapter/transport, not accepted as MAF's self-report. Missing usage is `unknown`, never zero. |
| `ExecutionReceipt` | Attempt/envelope/charter/manifest/definition digests; ordered request, decision, grant, dispatch and result IDs; MAF checkpoint reference; artifact references/hashes; terminal status and unresolved unknowns | Sealed by Flow outside worker write scope. A first-slice receipt may state that no code artifact or Git commit was produced; it cannot imply a commit-bound handback. |

Do not send raw credential values, host secrets, or unconstrained filesystem paths in the envelope or protocol. Treat MAF messages and child output as untrusted input. The task text can be a size-bounded run-local file referred to by Flow-controlled path/digest, or a size-bounded protocol field; either way Flow validates it before use. A grant is bound to the exact action and expires after one dispatch. It is an internal Flow ledger capability, never a provider credential given to MAF.

## Child-process protocol and state invariants

Use a single child spawned with `subprocess` argument vector, no shell. For the first slice, framed line-delimited JSON over the child's stdin/stdout is enough; stderr is bounded diagnostic output only. The parent is the only process that opens the execution ledger or calls the local adapter. Messages carry `protocol_version`, `attempt_id`, monotonically increasing `message_id`, and `type`; correlate every response to a request ID. Minimal sequence:

1. Flow validates run/assignment, commits attempt and envelope, then starts the MAF child and sends `start` with envelope and task reference.
2. The guarded MAF participant sends `propose_action`; the parent validates binding and calls the Flow policy gate. Parent replies `action_decision` with denial or a grant-bound normalized worker result after it invokes the local adapter. The child cannot call the local adapter directly.
3. The child sends `checkpoint_ref` and `workflow_finished` with trace/checkpoint references and synthesis. Flow verifies that all actions are terminal, records the checkpoint link, seals the receipt, and reports the attempt outcome.
4. EOF, malformed/oversized messages, wrong attempt/version, timeout, or child crash cause a recorded failed or `unknown` attempt. If dispatch might have reached the adapter without a durable observed completion, mark that action `unknown` and require manual reconciliation; do not retry it automatically.

Transactional invariants: one action ID maps to one immutable request; one allowed decision reserves one delegation and concurrency slot; one grant can be consumed once; a denial yields zero adapter calls; an `unknown` action still occupies its policy budget and blocks replay; a replayed ID returns its stored disposition or halts for reconciliation. A new attempt must not erase prior grants or dispatches. The six/three/two limits and role allowlist are enforced by the SQLite gate with `BEGIN IMMEDIATE` or equivalent serialization, not by MAF round settings. The first worker uses one delegation and zero replans; tests still exercise the hard boundaries as contract tests. Persist checkpoint identity as a reference after Flow actions are committed; MAF checkpoint state cannot grant a new dispatch. Treat exact-once physical invocation as unproven across mid-call crashes; fail closed with `unknown`.

The initial IPC trust model is one locally spawned child whose standard streams are private to the supervising CLI; it does not expose a socket or remotely accessible endpoint. Keep protocol parsing strict and isolate MAF dependencies in that child. A future daemon/MCP transport needs its own authentication design and must call the same Flow gateway rather than reuse stdio assumptions.

## Verification and handback

1. Contract round trips and migration tests run in the base Python environment with MAF absent. Reject altered digests, unsupported schema, duplicate action ID with different payload, expired/reused grant, missing definition, and a manifest assignment outside the allowlist.
2. Ledger tests use competing requests to prove six-delegation, three-concurrent, two-replan, provider, and zero-paid limits. A denied action must leave the fake adapter call count at zero. Replay and `unknown` must never produce a second call.
3. Protocol tests use a fake child to cover valid exchange, malformed line, oversized payload, EOF before result, timeout, crash during adapter call, and mismatched attempt/action IDs. Verify durable status and process cleanup.
4. One integration test launches the optional MAF runner through the real CLI with a fake local adapter; one opt-in manual smoke uses local Ollama and the effective `test-engineer` role. Both inspect the receipt against ledger rows, definition hash, and actual adapter observations. No Codex or Claude calls.
5. Run the existing Flow unit suite, CLI help check, `flow run verify`, `flow run validate-orchestration`, `git diff --check`, and a fresh install smoke showing ordinary Flow CLI commands work without MAF installed. Independent review should inspect the deny path and receipt claims before handback.

**Main risks:** The prototype's same-process replay ID proof does not establish durable replan IDs or restart safety; those are later slices. MAF checkpoint format and package versions need pins and an incompatible-checkpoint error rather than silent resume. The first local Ollama model may have nondeterministic text, so acceptance checks authorization, call observation, hashes, and bounded completion rather than semantic answer quality. The CLI's existing append-only lifecycle files are not a concurrent policy ledger. Receipt sealing and artifact truth cannot be inferred from a child message. Measure actual integration effort against the Flow-native machinery estimate later; the earlier 70% target is not evidence of savings.

# Architecture review: adopting MAF as Flow's execution runtime

## Basis and scope

The target is an adoption path, not a vote on whether MAF is desirable. The Shaper produces an approved, revisioned charter; Flow remains the authority for lifecycle, policy, permissions, budgets, evidence, memory, and handback; MAF/Magentic coordinates execution; provider adapters invoke Codex, Claude, and local workers. The previous single-worker [solution](../../execution-provider-receipt-charter/solution.md) preferred a direct Codex SDK first proof. Andy's later target architecture and this run's [requirements](../requirements.md) supersede that execution-order preference for this design exercise. Neither source authorizes changing production runtime behavior in this run.

**Observed repository boundary.** Flow is presently a Python standard-library CLI with a runtime-neutral framework, project overlays, and generated Claude/Codex surfaces ([`.flow/PROJECT.md`](../../../PROJECT.md), [`docs/architecture.md`](../../../../docs/architecture.md), [`cli/flow.py`](../../../../cli/flow.py), [`cli/sync.py`](../../../../cli/sync.py)). `cli/runstate.py` is the sole lifecycle writer: `run.json` is its projection and `events.jsonl` its history. `cli/orchestration.py` structurally validates `orchestration.json` at dispatch, handback, and acceptance; it explicitly does not attest effective runtime grants or provider behavior ([ADR 0001](../../../../docs/adr/0001-separate-orchestration-contracts.md), [Orchestration Safety](../../../../scaffolds/default/standards/orchestration.md)). There is no production MAF runtime or Flow MCP server in the inspected CLI. Thus MCP is a proposed ingress to the same Flow application boundary, not an integration point already implemented.

## Ownership and proposed control path

| Owner | Responsibility | Durable output |
| --- | --- | --- |
| Shaper | Align charter, including outcomes, scope, limits, and delegated approval envelope; approve allowed expansion or escalate. | Charter revision and decision identity, stored by Flow. |
| Flow application/policy | Validate charter and assignment, reserve a delegation/replan/budget slot, enforce specialist and provider grants, issue stable request and attempt IDs, decide approval, reconcile unknown work, accept handback. | Run-linked policy decisions, dispatch ledger, approval decisions, receipt, lifecycle transitions. |
| MAF/Magentic | Build execution plan, request specialists, coordinate parallel work and handoffs, maintain recoverable workflow state, emit execution events. | Checkpoint and trace, linked by Flow IDs; neither is authoritative policy or final evidence. |
| Provider adapter | Translate a Flow-approved specialist request into Codex SDK/App Server, Claude Agent/Claude Code, or a local inference client; return provider events and usage. | Provider session/result references and normalized observations, with unverified fields marked. |
| Flow observer/verifier | Inspect Git/worktree delta, validation, artifact contracts, and provider handback outside worker write scope; retain producer/verifier separation. | Commit-bound, independently observed receipt and reconciliation disposition. |

**Proposed sequence:** chat/CLI ingress → Flow resolves approved charter revision and existing `orchestration.json` assignment → Flow opens an execution attempt and hands MAF a bounded, immutable execution envelope → every MAF specialist request or replan enters a Flow-owned gate before adapter construction or provider call → Flow durably reserves the request, then MAF invokes a provider through a guarded adapter → provider events and MAF checkpoint IDs are correlated to the Flow attempt → Flow observer builds receipt, reconciles unknown work, and alone advances the existing lifecycle handback gate. A Shaper approval is a Flow policy decision bound to charter revision, action, scope, budget, expiry, and approver identity; a MAF human-input message only transports the request/response. A deny or ambiguous replay halts dispatch and surfaces reconciliation.

The first launch surface should be a Flow CLI application command attached to an existing run and its `orchestration.json`. Later MCP tools should call that same application service. This is a **proposal**, inferred from the current CLI and lifecycle seams; no production command or MCP endpoint implements it yet. Preserve Flow-owned schemas between the gate and runtime so MAF payloads and checkpoint format do not become Flow's domain model ([Architecture Standard, “Layering” and “Domain and integration boundaries”](../../../../scaffolds/default/standards/architecture.md)).

## Two viable embedding shapes

| Shape | Benefits | Costs / integration risks | Reversibility |
| --- | --- | --- | --- |
| **A. Optional in-process MAF package** imported by a new Flow execution module only when invoked | Shortest call path, simple local debugging, direct callback into policy and receipt services. | Pulls MAF and provider dependencies into Flow's stdlib CLI interpreter; async workflow and provider failures can affect the CLI process; hard to supervise an interrupted worker independently. | Moderate if all MAF types stay behind Flow-owned request/event contracts. |
| **B. Separate local MAF runner process, with Flow CLI as supervisor and gate** | Keeps core CLI/develop install usable without MAF dependency; isolates crashes and provider SDKs; makes restart/unknown-state reconciliation explicit. Supports a replaceable runtime later. | Needs a small versioned local request/event protocol, process supervision, authenticated local IPC or tightly scoped files, and a durable Flow gate accessible at every dispatch. A callback protocol can become an accidental second scheduler if overbuilt. | Higher, provided Flow's contract is stable and checkpoints stay runtime-owned. |

**Recommendation for design capture:** pursue B as the first production integration shape, with a narrow local protocol and one guarded construction path. The stdlib CLI constraint and observed mid-call crash behavior make process isolation useful. Keep A as a lower-effort fallback for an initial constrained implementation if supervision proves disproportionate. In either shape, the execution contract is the portability seam; MAF owns mechanics, Flow owns decisions. Record the runtime embedding and state-ownership decision in an ADR before production dependency changes ([Architecture Standard, “ADR convention”](../../../../scaffolds/default/standards/architecture.md); [Solutioning Decisions, “Option comparison and rationale”](../../../../scaffolds/default/standards/solutioning-decisions.md)).

## Evidence, issues, and verification

The four runs prove a sequence of narrow capabilities, not a production runtime. The first real MAF concurrent run invoked existing Flow role definitions through Codex, Claude, and Ollama, and Magentic reached plan review. It also breached the approved cost stop rule because subscription-backed Codex did not expose a reliable dollar cap; its [review](../../maf-delivery-runtime-spike/review.md) requests changes, and its [receipt](../../maf-delivery-runtime-spike/research/receipt.json) explicitly leaves provider results unattested. The [control/recovery run](../../maf-runtime-control-recovery/HANDOFF.md) added a run-local SQLite Flow gate, denied unmetered paid dispatch, and resumed a post-worker checkpoint in another process. The [interruption run](../../maf-magentic-interruption/HANDOFF.md) got an actual Magentic participant request through the gate, denied a disallowed specialist without dispatch, and required manual reconciliation after a local Ollama call was interrupted. The [multi-turn run](../../maf-multiturn-policy-gate/HANDOFF.md) gave two stub specialist calls distinct replay-stable IDs, halted a replay without another ledger dispatch, rejected raw participants through its *local* builder, and denied Magentic's third replan. Its [review](../../maf-multiturn-policy-gate/review.md) notes that construction enforcement and restart-stable replans remain unproved.

| Integration issue | Proposed owner and slice | Verification criterion |
| --- | --- | --- |
| **A bypass can call MAF without Flow authorization.** The tested builder guards one path, not all production entry points. | Flow runtime lead: central execution gateway, guarded factory, and CLI call path; no raw participant/agent insertion from the application layer. | Enumerate every launch/delegation/replan entry point; integration test each denial with zero provider adapter calls and zero unauthorized lifecycle transitions. |
| **Replay and unknown side effects.** Request IDs worked in one same-process replay, but replan counter is memory-only; a mid-call result is unknowable after crash. | Flow state owner and runtime lead: durable attempt/request/replan IDs, reservation/unknown states, checkpoint links, explicit reconciliation. | Kill between reservation, provider start, first output, and completion; resume in a separate process; show stable ID, no silent retry or duplicate dispatch, and a user-visible reconciliation state. |
| **Paid spend is not bounded by the prior Codex path.** Token usage or subscription login is insufficient as a hard dollar stop. | Provider adapter owner and Flow policy owner: fail closed for any paid route without reliable pre-dispatch budget reservation and enforceable provider/session limit; account for all calls. | Exhaust budget and simulate missing/late usage; prove dispatch denied before physical provider call; independently reconcile charge and cap. Keep Codex paid work blocked until this is shown. |
| **Approval authority could drift from charter.** | Flow policy owner and Shaper owner: revision-bound delegated authority matrix with expiry, revocation, scope/risk ceiling, and escalation. | Allowed, expired, revoked, over-budget, risk-expanded, and human-only transition cases; prove MAF messages cannot grant authority or write lifecycle state. |
| **Receipt and artifact truth are not yet independent.** Current probes have no worker commit; provider output and physical call counts are not fully attested. | Flow observer/verifier owner: versioned receipt outside worker write scope; Git baseline/delta/commit readback, validation, artifact contract, provenance, provider session, checkpoint, and decision links. | One real worker commit and tamper/unauthorized-delta cases; independent readback of receipt inputs; unknown evidence prevents accepted handback. |
| **Specialist portability is only partial.** Three role files were hashed/injected, but shared artifact contracts, relevant memory, repeated role instances, and full 13-role mapping were not exercised. | Runtime adapter owner with role owners: compile canonical role definitions and instance-specific briefs into each provider's native shape. | Contract fixture across Codex/Claude/local; two distinct instances of one role; verify input digest, permissions, outputs, and producer/verifier separation. |
| **MAF version, dependency, and observability coupling.** Probes use a disposable MAF environment and run-local SQLite; release packaging and trace correlation are absent. | Maintainer/runtime lead: pin tested MAF package set, define upgrade compatibility and rollback, correlate Flow ID ↔ MAF checkpoint/trace ↔ provider session. | Fresh install and CLI smoke without MAF; opt-in runtime install; restart across an upgrade boundary or explicit incompatible-state block; structured trace of deny, unknown, approval, dispatch, and handback without secrets. |

Suggested delivery order: (1) Flow-owned execution/charter/receipt contracts and ADR; (2) runner packaging and single guarded local specialist through the real CLI; (3) durable gate/replay/replan and restart reconciliation; (4) independent commit-bound handback and delegated approvals; (5) Codex/Claude/local adapter migration and multi-instance roles; (6) MCP ingress over the established Flow gateway. This sequence is a design proposal, not a claim that the current CLI, manifests, or run-local spike already implement it. The earlier roughly 70% Delivery Lead reduction target should be converted into a component-level estimate during planning; the existing evidence does not establish that percentage.

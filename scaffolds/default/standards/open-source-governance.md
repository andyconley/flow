# Open Source Governance Standard

This standard defines how projects manage licensing, contributions, and open-source hygiene.

## License awareness

Projects should understand the licenses in their dependency graph and document unacceptable or high-risk license classes.

## Contribution model

Projects should choose and document a contribution agreement model, such as:

- DCO
- CLA

The chosen model should be explicit so contributors are not surprised by legal or process requirements.

## Repository governance

Useful governance practices include:

- automated license checks
- repository health checks
- explicit release discipline
- documented contribution guidance

## Community health

If a project is open source or depends heavily on OSS, measure more than stars:

- contributor responsiveness
- bus factor
- maintenance activity
- security hygiene

## Relevant standards and tools

Principles:

- license compliance
- explicit contribution policy
- automated repository health checks

Common tools:

- license-checker / FOSSA-style tooling
- REUSE
- OpenSSF Scorecard
- CHAOSS metrics

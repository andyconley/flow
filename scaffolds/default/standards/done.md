# Definition of Done

This standard defines the minimum bar for calling work complete.

## Minimum categories

- build passes
- tests pass
- review completed
- docs updated as needed
- risks and deviations recorded

## Default expectations

- code should satisfy the active architecture and collaboration standards
- new behavior should be validated at the appropriate level
- required handback evidence should exist
- known deviations should be recorded, not hidden

## Project tightening points

Projects should tighten this with:

- deploy requirements
- runtime verification requirements
- E2E expectations
- observability or logs-review expectations

## Relevant principle

Definition of done is evidence-based. Completion means the change satisfies its standards, validation expectations, and handback obligations, not merely that the code was written.

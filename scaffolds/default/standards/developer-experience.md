# Developer Experience Standard

This standard defines how teams reduce friction between an engineer and shipping value.

## Core principle

The right path should be easier than the improvised path.

## Cognitive load

Teams should identify and reduce extraneous cognitive load from:

- bespoke environment setup
- tribal knowledge
- inconsistent tooling
- unclear ownership

Intrinsic product complexity is the job. Extraneous friction is the platform backlog.

## Golden paths

Projects and platform teams should provide supported defaults for common tasks such as:

- service scaffolding
- local development
- CI/CD
- documentation setup
- runtime configuration

Golden paths are not mandates; they are the paved road the team commits to support.

## Local development standardization

Use a consistent local development approach where practical, such as:

- dev containers
- reproducible environment tooling
- preview or ephemeral environments for validation

## Self-service and portals

For larger organizations, consider service catalogs, scaffolding portals, and self-service infrastructure as ways to reduce repeated manual work.

## Relevant standards and tools

Principles:

- cognitive load reduction
- internal developer platforms
- golden paths

Common tools:

- Backstage
- dev containers
- Devbox / Nix-style reproducible environments
- service catalogs and scaffolding systems

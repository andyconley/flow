# Architecture options research
Status: recommendations pending engineer decision; not an approved solution.
Question: Which existing extraction and interactive presentation approach fits the approved flat Python CLI pilot?
Evidence: approved requirements; standards/architecture.md (Core principles, Domain and integration boundaries, ADR convention); Tach configuration/commands https://docs.gauge.sh/usage/configuration/ and https://docs.gauge.sh/usage/commands/; Cytoscape.js https://js.cytoscape.org/; Pyan3 https://github.com/Technologicat/pyan; Grimp https://grimp.readthedocs.io/en/stable/usage.html; Pydeps https://pydeps.readthedocs.io/en/latest/ . Primary docs inspected September10,2026 by solution architect and coordinator.
A recommended: Tach 0.35.0 map/check/report feeds Flow-owned normalized immutable JSON and a local bundled Cytoscape.js viewer. One graph authority; no language analyzer code. Viewer provides pan/zoom, selection, component filtering, node/edge drill-down into supporting source, before/after overlay, evidence status. No remote tach show --web. Viewer version and transitive package hashes to lock during pilot environment setup; no unverified version invented.
B viable fallback: Tach policy checking and Pyan3 HTML/SVG interactive graph output. Less viewer scaffolding, but two dependency interpretations need reconciliation and source-edge/delta joins still require work. Verify Pyan3 HTML affordances before selecting; current evaluation is documentation-only. Graphviz and GPL license affect packaging. Neither option demonstrated end-to-end.
Rejected: Grimp/Import Linter require importable package roots; do not restructure Flow imports to fit. Pydeps is weaker for exact edge source evidence and complete inventory.
Observed feasibility correction: Tach map works; check/report mistake cli/setup.py for legacy packaging until analyzer-only cli/pyproject.toml declares metadata in the isolated copy. That overlay must be recorded, excluded from source identity and never copied to production. Source hashes still identify unchanged Python. Report raw flag removes line detail, so retain non-raw source report or documented JSON diagnostics with complete edge matching; unjoined edges are inconclusive. Probe all-denied diagnostics are instrument output, not architectural findings.
45 CLI source files represented in map union,151 edges,34 keys with outgoing edges. Scan whole CLI for complete edge/cycle context, focus UI and policy pilot on harvest/collectors/watermark/store plus adjacent context. Roots: harvest.py,codex_collector.py,claude_collector.py,jsonl_watermark.py,usage_store.py; adjacent nodes include session_lookup.py,plugin_usage.py,paths.py. Whole-CLI extraction is context, not full-repo mutation or enforcement adoption.
Boundary proposal: shared jsonl_watermark must not import either collector or harvest orchestration; collectors must not import harvest. Check only new cycles against baseline, preserving existing cycle inventory. These rules are recommendations for approval, not inferred from current graph.
Five dimensions: domain—Flow owns evidence contract, analyzer owns import semantics; interfaces—source identities to raw reports to normalized delta to quality join to local viewer; persistence—immutable files, no service/database; operations—isolated pinned environment and no runtime/viewer network; durability—replaceable adapters, evidence/result semantics stable, ADR if expanded.
Confidence: high for smoke-tested flat source extraction and reporter; medium for bounded integration; mutation and interactive UX unproven.

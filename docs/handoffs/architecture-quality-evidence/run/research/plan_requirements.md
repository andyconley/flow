## Cross-chunk contract and failure semantics

- **Recommended:** define one machine-readable top-level verdict: `pass`, `fail`, or `inconclusive`, plus per-capability state `available`, `unsupported`, `failed`, or `absent`. Preserve native mutation statuses under the mutation capability rather than collapsing them into the verdict.
- **Recommended:** `fail` is reserved for a valid, complete evaluation that finds a newly introduced prohibited edge/cycle or an intentionally failing fixture. Evidence integrity, provenance, inventory, analyzer, mapping, policy-binding, and required-quality gaps are `inconclusive`. Optional unsupported metrics are visible `unsupported` and do not substitute for required selected-function evidence.
- **Recommended:** make the review packet immutable by content digest and bind its snapshot pair, policy digest, analyzer overlay digest, and raw-artifact digests together. A viewer can display an analysis overlay, but the overlay must be separately identified from the source checkout.

## Contradictions and planning gaps

- **Observed conflict, resolved by approved clarification:** A3 says required evidence “cannot pass,” while the clarification says absent/stale/incompatible evidence is **inconclusive**. The plan must implement the latter explicit state; the isolated checker may still return a non-zero outcome for both `fail` and `inconclusive`.
- **Observed ambiguity:** solution material names the v0.28.0 collector/watermark area, while the handoff says that baseline is evidence, not an automatically selected implementation base. The plan must record the exact isolated checkout revision and selected area before artifacts are generated; do not treat the research archive as the pilot checkout by implication.
- **Observed gap:** the contract lists raw references but does not define canonical serialization, digest algorithm, source-span coordinate convention, or whether policy comparison can start after partial inventory. These must be specified for A1/A2/A3 to be testable. Recommended defaults: canonical JSON, SHA-256, 1-based file line spans, and no policy `pass` when any in-scope inventory item is unclassified.
- **Observed gap:** rules describe direct imports, but the evaluator needs an explicit rule match contract for direction, scope, exception identity/expiry, and how a rename/move affects the baseline join. The requirements already prohibit silent coverage inheritance; apply the same explicit old/new mapping rule to graph identities.
- **Observed gap:** the local browser requirement names interactions but no report-delivery contract. Specify a static report or a locally bound server, its entry command, artifact root, no runtime network dependency, and drilldown behavior when the source checkout is unavailable. This is needed to verify a standalone report rather than a developer-machine viewer.

## Mutation and reviewer-experiment feasibility

- **Mutation: conditional feasibility.** Radon and coverage have been exercised against isolated source, but mutmut has not. Chunk 3 therefore begins with a compatibility/provenance checkpoint, using the selected collector test nodes and a deliberately weak/then strengthened assertion. If it cannot prove workspace path loading, baseline-test success, and the selected mutant execution, record the raw failure and evaluate Cosmic Ray as the pre-approved alternative; do not build a mutation engine or claim A5.
- **Reviewer experiment: feasible as directional evidence.** The four bounded changes/two matched-pair protocol is implementable with one exploratory engineer because the frozen oracle, supplied material, counterbalanced order, and separate preparation timer limit several confounders. It cannot establish general reviewer speed or statistical significance, and same-reviewer learning plus expectation bias remain. Record those limitations with the results; a second reviewer is a follow-on expansion study, not a condition of this pilot.

## Planning disposition

The four chunks can be planned together if Chunk 1's evidence contract and Chunk 2's verdict semantics are hard prerequisites for Chunk 3/4 artifacts. Chunk 3's mutation checkpoint is a stop-and-decide boundary: incompatibility leaves the broader pilot unapproved until its documented alternative decision is reviewed. Chunk 4 can measure usefulness only after the packet is candidate-bound and the seeded oracle is frozen.
